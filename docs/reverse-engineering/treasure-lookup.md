## Confirmed static rules

| Rule | Native evidence |
| --- | --- |
| Treasure rows contain separate reward entries; a contents table is not itself an acquisition route | `TreasureData.NewGame` 0x1634164 builds the ten possible reward entries. It skips ID -1, not ID 0. |
| Each ordinary analysis entry receives its own percentage roll | `AISystem.UpdateTreasureAnalysing` 0x14ab378, especially 0x14abbb0–0x14abc5c: enumerate entries, `Random.Hits(Rate)`, append each success. No weighted single-choice roll across contents. |
| Item quantities include both ends of the range | `Random.Rand(min,max)` 0x145ff98 uses modulo `(max-min+1)` plus min. Exact PRNG modulo bias is not modeled by the website. |
| Percentage checks differ from terrain checks | `Random.Hits` 0x1460024 compares `Rand(100)` with rate; `Hits1000` 0x1460084 compares `Rand(1000)` with rate. |
| Gathering uses the resolved terrain's drop group and area level | `ScrGather` 0x1485d2c, 0x1486d30 onward: group -1 is skipped; `Hits1000(itemDropRate)`; area lookup; inclusive `Rand(minDropNum,maxDropNum)`; filter eligible treasure rows and select a random entry for each box. |
| Group and level eligibility are explicit | Predicate 0x14da558: Treasure.group == Terrain.dropGroupId; Treasure.minLevel <= Area.level <= Treasure.maxLevel. Selection is `Where` → `ToArray` → `RandomOrDefault` at 0x1486ee0–0x1486ef4. Overlapping rows remain separate candidates, including rows with identical names. |
| A tile's visible state matters | `GetTerrainData` 0x148cdb4 and predicates 0x14da20c/0x14da284 match natureGroupId and texture ID against nature or terrain; fallback is MapChip.terrainData. `ScrGather` also has a type/dataId/SEB-frame fallback, predicate 0x14da4b4. |
| Soil types differ from untouched biome terrain | `BaseMapGenerator` constants in dump.cs: 0 water; 1 ground; 2 grass; 3 sand; 4 rock; 5 volcano; 6 snow; 7 swamp; 8 snow soil; 9 desert soil; 10 volcanic soil; 11 rocky soil; 12 swamp soil; 13 grassland soil. |
| Ordinary monster drop path checks type 0 and dropDataType 2 | `EnemyBaseSystem.DropItem` 0x15681ec: reject allies, nonzero monster type, missing drop data; roll dropRate with Hits; call DropTreasure only for dropDataType 2. |
| Monster drop is a direct treasure reference | `DropTreasure` 0x1568a7c → `MonsterData.GetDropData` 0x18e38e4 uses dropDataId. `World.CreateTreasure` 0x1479898 indexes that row. This path does not reapply the gathering selector's min/max levels. |

The base probability for one positive-quantity reward entry after an ordinary defeat is `monster.dropRate / 100 × reward.rate / 100`. If the same item occurs in multiple entries, the monster-loot module combines independent misses for at-least-one probability, and sums expected quantities. The displayed species mean assumes equal species weights; it is not the real encounter-weighted farming probability.

Example: Pretty Cloth has a Sand/Desert soil route through Wooden Box #57 at levels 50–999, with a 70% contents entry and quantity 1–3. At level 50, its group contains 11 eligible rows. The regular Sand records have base treasure checks of 4.5–5.3%; Desert soil has 8%. These are conditional checks for matching gatherable tile states, not a blanket probability for every player dig. Falcone references box #221 with a 5% base drop check and a 70% Pretty Cloth entry, giving 3.5% after analysis before other effects.

## Field interpretation

`id` is a direct row index; `group` is used by group-selecting callers. `name`, `res`, `img` identify the box and its visual. `minLevel`/`maxLevel` are caller filters, not universal availability bounds. `hp`, `rank`, `week` and `flag` are preserved without treating them as universal gating rules. Metadata names the flags SPECIAL=1, SCORE_RANKING=2, NON_LOST=4 and PVP_REWARD=8; these names do not prove every effect of the flags.

The contents comprise equipment slots 1–3; item slots 1–3 with min/max quantity; one each of furniture, valuable, skill and job. Each has its own rate. Additional `source`, resolved names and summary columns in Treasure_lookup are spreadsheet annotations, not native Treasure fields.

Rows 801–805 and 808–815 have minLevel greater than maxLevel in the original APK. Keep those values. They cannot match the inclusive level selector, but a direct-ID caller can still access them. Do not silently repair the numbers or declare them globally unobtainable.

## Strongly supported links with incomplete conditions

- Area opening: `AreaSystem.OpenArea` 0x14deb0c creates the area treasure ID (AreaData +0x4c) at 0x14df070. The surrounding placement/area lifecycle is not fully traced.
- Survey result: `SubForm.UpdateSurveyResult` 0x16f860c creates SurveyData.rewardTreasureId (+0x40) at 0x16f8e68. Success, earning limits, timing, job eligibility and selected survey availability remain separate questions. Direct IDs explain why the row's gathering-level range must not be treated as a universal constraint.
- Special-boss guerrilla prize: `BattleSystem.AddGuerrillaPrize` 0x14ed618 checks isGuerrilla, gets SpecialBoss.rewardGroupId (+0x40), filters on group alone (predicate 0x14f35d0), chooses one random row and appends one prize. This refutes using only the first matching row. Follow-up: `FighterSystem.EnterLeaving` 0x1586a80 gates the call to rival team 1, a monster entity, non-PvP, guerrilla mode, and equality with the rival TeamMember.Leader entity ID at 0x1586dd0–0x1586de4. It does not award a group box for every follower. `BattleSystem.Finish` 0x14ed864 requires result Victory (1) for guerrilla rewards, filters treasure prizes, and calls FireTreasure at 0x14edc1c. FireTreasure 0x14f0118 creates the selected treasure ID in the world at 0x14f029c. These non-SPECIAL rows then use the ordinary analysis path.
- Dungeon internal boxes: `DungeonConquestSystem.PlaceTreasures` 0x15432dc checks treasureRate and iterates the first internal treasure-table list with per-entry Hits calls, retrying selection when none succeed. It is not the same selector as terrain treasure groups, and raw percentages cannot simply be advertised as normalized item drop probabilities. Completion rewards are separate.
- Attack-triggered drop: predicate/action 0x14d7298 can call DropTreasure after a SkillData field percentage check; its parent `AISystem.OnAttack` conditions remain to be recovered. Do not add it to ordinary defeat odds yet.
