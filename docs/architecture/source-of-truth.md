# Source Of Truth Map

This site is a Kingdom Adventures reference database. Game facts should have one canonical home, then pages should render from that home.

## Relationship Domains

Jobs are central. A job can affect:

- buildings and shops it can open
- survey capability
- marriage and child outcomes
- equipment access
- skill access
- ranks, stats, and ranges
- guide previews and search results

When changing any job-related fact, check whether the fact also affects Jobs, Houses, Survey, Marriage, Guides, Shops, Loadout, or Search.

## Page Rules

Pages may own:

- local UI state
- filters and sorting state
- view-only formatting
- page-specific explanatory text

Pages should not own:

- game relationship mappings used by more than one page
- shop/building/job compatibility facts
- route/name normalization helpers used by multiple pages
- category colors used across pages

Treasure lookup follow-up (2026-09-11): `native-treasure.json` also owns original SpecialBoss reward groups and appearance terms. `lib/treasure-lookup.ts` decodes the traced weekday term; `lib/item-sources.ts` owns the shared item-to-box and box-to-source reverse index, separating contents `rate` from acquisition `boxRate`. `searchTreasureBoxes` searches event sources as well as contents. The older manual `special-boss-loot.ts` consumers still need migration; they are not evidence for native selection or reward counts.

Original monster map poses: `src/game-data/monster-sprites.json` via `src/lib/monster-sprites.ts`, generated by `RE-evidence/20260911-treasure/export_monster_sprites.py` from Monster.img and original monster archive. Used by Item Sources; separate from legacy wiki monster icons.

Skill craftability: `src/lib/skill-crafting.ts` reads Skill.csv flag2 and requirements; both Skills and Item Sources consume it. Prices are not craftability evidence. Daily rank sources join `DAILY_RANK_REWARDS.sourceRowId` to native Treasure rows; Item Sources groups them by day/rank.
