## Shared sources and regeneration

`src/app/seo.ts` owns search titles/descriptions. `src/app/seo-policy.ts` owns canonical aliases and indexing policy. `search-route-catalog.json` is generated from `App.tsx`, the existing bundled shared job names, and `SHOP_RECORDS`; it contains only public route identities.

`npm run seo:prepare` refreshes the route catalog. The production build runs preparation, Vite, `seo:generate`, then `seo:render`. Rendering is a bounded local batch (configurable `SEO_RENDER_WORKERS`, default up to four), uses the same public data/UI and allows only GET requests. Repeated public API reads are cached within the build. It does not submit analytics, edit profiles or call model APIs. Dynamic timers/canvases and personalized state continue updating with JavaScript. If public routes change, run `seo:generate -- --update-config` after building and commit the generated Vercel rewrites and sitemap. Generation fails on uncommitted routing drift rather than silently publishing broken deep links.

## Indexing follow-up

The 14 crawled-not-indexed URLs contain a mixture of duplicate/filter URLs and unique tools. Consolidate exact duplicates and filters; inspect `/survey` and `/monster-pet-stats` as unique canonical pages. Do not request indexing for all alternate URLs. Submit the maintained sitemap after verifying the deployed response, then request indexing for selected canonical pages. Google decides whether and when to index them.

Official guidance: [JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [Vercel rewrites](https://vercel.com/docs/rewrites).

Google explicitly includes interactive tools and expandable sections as main content in its [helpful content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content). Its [crawler guidance](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading) explains that Google generally does not click buttons to load content. The implementation therefore serves help text upfront and collapses only its display. This improves accessibility to content, not a guarantee of indexing or ranking.
